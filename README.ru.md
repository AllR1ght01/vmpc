# vmpc

**Терминальный чат-клиент для LLM API.**
Потоковые ответы, отдельный канал рассуждений в реальном времени, рендерер
markdown, сделанный именно для терминала, а не для браузера — и интерфейс,
говорящий по-английски или по-русски вживую, без перезапуска.

Это не IDE и не агентный фреймворк — это быстрый способ общаться с моделью
из терминала, не отрывая рук от клавиатуры, с набором мелких удобств
(сохранённые чаты, режимы промпта, файловый контекст), которые делают это
приятным занятием каждый день.

## Возможности

|  |  |
|---|---|
|  **Любой эндпоинт** | В формате OpenAI или Anthropic: официальные API, Groq, Together, vLLM, LM Studio, OpenRouter, шлюзы Bedrock, прокси. Один мастер `/api add` покрывает формат протокола, схему авторизации и способ хранения ключа (статично, через переменную окружения или shell-командой — 1Password, `pass`, vault). |
|  **Канал рассуждений** | Вывод reasoning-моделей стримится в отдельную секцию, синхронизированную с основным ответом, чтобы ни один из каналов не "голодал". |
|  **Markdown для терминала** | Рендерер, сделанный именно под терминал, а не под браузер — блоки кода, таблицы, инлайн-форматирование, без зависимости от headless-браузера. |
|  **Режимы промпта** | `/mode` переключает именованные системные промпты прямо посреди разговора, каждый может открывать свой набор команд. Можно написать свой через `/mode add`. |
|  **Файловый контекст** | `/context` подключает папку или файл, перечитывая их с диска на каждом ходу — контекст не может устареть, а сохранённый чат не разрастётся до копии вашего репозитория. |
|  **Сохранённые чаты** | Каждый разговор — это JSON-файл на диске, с автоматическим названием от модели после первого обмена репликами, доступный для возобновления по id. |
|  **Двуязычный интерфейс** | `/lang` переключает *собственный* текст vmpc — не ответы модели — между английским и русским, мгновенно, без перезапуска. |
|  **Одноразовый режим** | `vmpc chat "..."`, `vmpc api list`, `vmpc models`, `vmpc chats` работают и без REPL, используя тот же конфиг, транспорт и рендерер, что и интерактивное приложение. |

## Установка

Нужен Python 3.10+.

```bash
git clone https://github.com/AllR1ght01/vmpc.git
cd vmpc
pip install -e .
```

Это подтянет `rich`, `prompt_toolkit` и `httpx` — все они либо чистый
Python, либо готовые wheel-пакеты, так что компилятор не понадобится нигде,
включая [Termux](https://termux.dev/) на Android.

## Быстрый старт

```bash
vmpc          # открывает интерактивный REPL — /api add проведёт через
              # настройку первого эндпоинта, если ни один ещё не задан
```

или вовсе без REPL:

```bash
vmpc api add                          # настроить эндпоинт один раз
vmpc chat "объясни, как работает DNS" # разово, без интерактивной сессии
```

## Команды

| Команда | Что делает |
|---|---|
| `/api` | добавить, переключить или изменить API-эндпоинты |
| `/model` | выбрать модель для активного эндпоинта |
| `/context` (`/ctx`, `/files`) | подключить папку или файл для чтения моделью |
| `/mode` | переключить режим промпта или написать свой |
| `/lang` (`/language`) | переключить интерфейс vmpc между английским и русским |
| `/reasoning` | переключить стриминг канала рассуждений модели |
| `/new` | начать новый разговор |
| `/chats` (`/resume`) | открыть сохранённый разговор |
| `/title` | переименовать чат или дать модели назвать его заново |
| `/status` | показать активный эндпоинт и расход токенов |
| `/clear` | очистить экран и начать заново |
| `/help` | список команд |
| `/quit` (`/exit`) | выйти из vmpc |

<details>
<summary><strong>🔧 <code>/mode dev</code> дополнительно открывает</strong></summary>
<br>

| Команда | Что делает |
|---|---|
| `/raw` | точный исходник последнего ответа, до рендера |
| `/render` | прогнать markdown через рендерер и показать результат |
| `/wire` | точный HTTP-запрос хода, ключ скрыт |
| `/ping` | измерить задержку до первого токена и пропускную способность |
| `/palette` | все стили темы и что поддерживает этот терминал |
| `/prompt` | полный системный промпт, действующий сейчас |

</details>

**Клавиши:** `enter` — отправить · `alt+enter` — новая строка · `esc` —
прервать выполнение · `ctrl+c` — очистить ввод (дважды — выйти).

## Конфигурация

Всё хранится в `~/.vmpc/config.json` — эндпоинты, активный режим, свои
режимы и выбор языка интерфейса. Редактировать вручную ничего не нужно —
каждое поле пишется командой (`/api`, `/mode`, `/lang`, `/reasoning`).

## Принципы устройства

Несколько решений, которые стоит знать перед погружением в код:

- **Режим — это промпт *и* его команды, специально в паре.** `/dev` — это
  не просто другой системный промпт, а другой набор инструментов.
  Разделение этих двух вещей означало бы, что нужно не забыть включить обе.
- **Подключённый контекст перечитывается, а не кэшируется.** Папка,
  подключённая через `/context`, обходится заново на каждом ходу — она не
  может разойтись с диском, а файл сохранённого чата не может незаметно
  разрастись до снимка вашего репозитория.
- **Текст интерфейса вычисляется лениво, а не на этапе импорта.** `/lang`
  обязан подействовать со следующей же напечатанной строки, а не после
  перезапуска — поэтому встроенные режимы, описания команд и подписи
  статуса вычисляются в момент показа, а не запекаются в константу модуля.
- **Одноразовый CLI и REPL — одна реализация.** `vmpc chat` — это не
  отдельный путь кода, который просто похож на основной: он использует ту
  же загрузку конфига, транспорт и рендер, что и интерактивное приложение,
  так что исправление в одном месте чинит оба.

## Разработка

```bash
python -m py_compile $(find vmpc -name '*.py')   # проверить, что всё собирается
python _smoke.py                                  # прогоняет сохранение/загрузку чатов
```

Полные соглашения — в [`CONTRIBUTING.md`](CONTRIBUTING.md) (пока только на
английском). В частности, докстринги по всему коду объясняют *почему* тот
или иной кусок сделан именно так, а не просто что он делает. Стоит прочитать
несколько соседних, прежде чем менять то, что рядом — часто самое важное
как раз в этом обосновании.
